# 自动化任务规则

> 本规则规范项目的自动化任务管理——哪些任务该自动化、怎么触发、日志写到哪、失败怎么告警。

---

## 一、什么任务值得自动化

**判断标准：重复执行 + 规则明确 + 忘了会出问题 → 自动化。**

| 自动化 | 不自动化 |
|--------|---------|
| 每天定时同步代码（git commit + push） | 一次性操作 |
| 每天定时归档对话总结 | 需要人工判断的内容创作 |
| 定时全量测试（引用一致性、接口、页面） | 需要人工交互的需求讨论 |
| 文件状态变更后自动更新索引 | 偶发的决策记录 |

**核心原则：自动化是兜底，不是依赖。** 自动化任务失败时不能影响主流程，要有 fallback。

---

## 二、三类自动化任务

### 1. 定时同步（Git Sync）

| 项 | 规则 |
|----|------|
| 做什么 | 检测文件变化，自动 commit + push |
| 触发 | 每天1次（如 23:50） |
| 实现 | 脚本检测 `git status` 有变化就提交，无变化跳过 |
| 日志 | 写到 `产出/任务日志/Sync.md` |
| 失败处理 | 日志记失败原因，下次重试；不阻塞其他任务 |

### 2. 每日总结（Auto Summary）

| 项 | 规则 |
|----|------|
| 做什么 | 读对话数据库 → AI分析 → 生成每日总结 |
| 触发 | 每天1次（如 18:30） |
| 实现 | 脚本提取当天对话，调AI分析，有内容才写文件，无内容不建空文件 |
| 日志 | 写到 `产出/任务日志/AutoSummary.md` |
| 多电脑 | 用机器名后缀区分文件（如 `-HOME`），避免 git 冲突 |
| 失败处理 | 日志记失败原因，不阻塞其他任务 |

### 3. 全量测试（Full Test）

| 项 | 规则 |
|----|------|
| 做什么 | 引用一致性、接口对应、页面完整性、文件引用全量检查 |
| 触发 | 每周1次（如周五凌晨1点） |
| 实现 | 脚本跑全量检查，生成报告 |
| 日志 | 报告存到 `产出/测试报告/`，执行日志写到 `产出/任务日志/FullTest.md` |
| 失败处理 | 日志记失败原因 + 退出码，下次重试 |

## 三、日志规范

### 日志文件位置

```
产出/
├── 每日总结/             # AI分析对话生成
├── 任务日志/
│   ├── Sync.md          # 定时同步执行日志
│   ├── AutoSummary.md   # 每日总结执行日志
│   └── FullTest.md      # 全量测试执行日志
└── 测试报告/             # 全量测试报告（每周一份）
```

### 日志格式

每次执行追加一行：

```
| 时间 | 结果 | 说明 |
|------|------|------|
| 2026-08-02 23:50 | ✅ 成功 | 提交3个文件 |
| 2026-08-01 23:50 | ⏭️ 跳过 | 无文件变化 |
| 2026-07-31 23:50 | ❌ 失败 | push失败：网络超时 |
```

### 日志查看

- 工作台前端有"自动化任务"页面，展示任务状态 + 执行日志
- 顶部栏铃铛图标，失败任务红点告警
- 日志文件本身也进 git，跨电脑可查

## 四、定时任务配置

项目 `scripts/` 目录下有脚本模板（sync.bat / sync.sh / auto-summary.js / plist），使用前搜索 `PROJECT_NAME` 替换成项目英文名。详细说明见 `scripts/README.md`。

### Mac（launchd）

改完 plist 里的 WorkingDirectory 后：
```bash
cp scripts/com.PROJECT_NAME.*.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.PROJECT_NAME.sync.plist
launchctl load ~/Library/LaunchAgents/com.PROJECT_NAME.auto-summary.plist
launchctl list | grep PROJECT_NAME  # 验证
launchctl unload ~/Library/LaunchAgents/com.PROJECT_NAME.sync.plist  # 卸载
```

### Windows（任务计划程序）

> 把 `PROJECT_NAME` 和 `PROJECT_PATH` 替换成项目英文名和项目绝对路径。

```cmd
schtasks /create /tn "PROJECT_NAME_Sync" /tr "PROJECT_PATH\scripts\sync.bat" /sc daily /st 18:50 /f
schtasks /create /tn "PROJECT_NAME_AutoSummary" /tr "PROJECT_PATH\scripts\auto-summary.bat" /sc daily /st 18:40 /f
schtasks /query /tn PROJECT_NAME_Sync  # 验证
```

时间建议：工作电脑 18:40 总结 / 18:50 同步，家用电脑 23:30 总结 / 23:50 同步。

## 五、失败告警

### 告警机制

1. 定时任务执行后写日志（成功/失败/跳过）
2. 后端接口 `/api/tasks/status` 返回各任务最新状态
3. 前端顶部栏铃铛图标，有失败任务时显示红色 badge + 抖动动画
4. 点击铃铛展开下拉，列出失败任务详情

### 告警处理

- 看到告警 → 点铃铛看哪个任务失败 → 看日志找原因 → 手动修复或重跑
- 不需要实时告警（不是生产系统），定时任务每天跑一次，第二天发现也来得及
