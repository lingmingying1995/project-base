# project-base · 项目地基包

> 建新项目时，clone 这个仓库作为地基，省去从0建规则的过程。
> 地基里放的是"AI 怎么跟你协作"的元规则，不是某个项目的业务逻辑。

## 这是什么

建第一个项目的时候，打地基（AGENTS.md、AI自检清单、规则文件）花了很长时间，一边踩坑一边补规则。建第二个项目时发现——如果不把地基模板化，每个新项目都要从0踩一遍。

这个仓库就是把第一个项目打地基的过程沉淀成模板。建新项目时 clone 下来改改项目信息就能用。

## 怎么用

### 1. clone 地基包

```bash
git clone git@github.com:lingmingying1995/project-base.git <新项目名>
cd <新项目名>
```

### 2. 改 git remote 指向新仓库

```bash
# 先在 GitHub 上建好新项目的空仓库，然后：
git remote set-url origin <新仓库地址>
```

### 3. 填写项目信息

打开以下文件，把【】里的提示语替换成实际内容：

- `AGENTS.md` — 项目名、项目描述、技术栈、日期
- `PRODUCT.md` — 产品定位、目标用户、功能范围
- `DESIGN.md` — 配色、字号、组件样式（如有UI）
- `AI自检清单.md` — 日期
- `规则/*.md` — 一般不用改，按需调整

### 4. 提交并推送

```bash
git add -A
git commit -m "feat: 基于地基包初始化项目"
git push
```

### 5. 开始干活

打开 opencode，AI 会自动读 AGENTS.md，从第一句话开始就知道"在这个项目里该怎么协作"。

## 地基包含什么

```
project-base/
├── README.md               # 本文件
├── AGENTS.md               # 开发规则（AI 必读）
│                            #   含"先确认再动手"7条核心协作规则
├── AI自检清单.md            # AI 反复犯的问题清单（空骨架，边做边加）
├── PRODUCT.md              # 产品说明（空骨架，填写项目信息）
├── DESIGN.md               # 设计规范（空骨架，如有UI才填）
├── agents/                 # 开发协作 Agent（4个）
│   ├── requirement-analyst.md  # 需求拆解员：编码前拆解需求
│   ├── architect.md            # 架构师：评估改动对结构的影响
│   ├── doc-maintainer.md       # 文档维护员：代码改了文档跟着改
│   └── code-tester.md          # 代码测试员：改完后检查关联模块遗漏
└── 规则/
    ├── 文件组织规则.md      # 一个内容单元一个独立文件 + 原话必留 + 索引维护
    ├── Git同步规则.md       # 攒着改 + 触发时提交 + 标准流程
    └── 新电脑初始化.md      # 环境初始化骨架
```

### Agent 协作流程

4个 Agent 按以下顺序协作，覆盖"需求→编码→验收"全流程：

```
用户说需求
  → 需求拆解员：拆成改动清单，用户确认
  → 架构师：评估结构影响，预警耦合和风险
  → 主Agent 编码
  → 文档维护员：同步文档
  → 代码测试员：检查遗漏
```

| Agent | 何时介入 | 做什么 | 改不改 |
|-------|---------|--------|--------|
| 需求拆解员 | 编码前 | 把用户需求拆成改动清单 | 不改 |
| 架构师 | 编码前 | 评估改动对结构的影响 | 不改 |
| 文档维护员 | 编码后 | 代码改了文档跟着改 | 直接改 |
| 代码测试员 | 编码后 | 检查"改了A没改B"的遗漏 | 只报告 |

**使用方式**：把 `agents/` 目录下的文件复制到项目的 `.skills-mirror/agents/` 或 `~/.config/opencode/agents/` 目录，opencode 会自动加载。如配了软链，直接生效。

## 地基包不包含什么

- 具体项目的产品功能定义（每个项目不同，写在 PRODUCT.md 里）
- 技术选型（每个项目不同，写在 AGENTS.md 里）
- 业务规则（如写稿规则、行业规范等）
- 代码（地基只管规则，不管代码）

## 核心理念

**规则管方向和底线，不管创意和判断。**

地基里的规则管的是"AI 怎么跟用户协作"（先确认再动手、不替用户决定、主动暴露盲区、不跨阶段提问等），不管"AI 怎么思考"（创意、判断、角度）。AI 在创意和判断上要主动发挥，不要被规则框死。

## 维护

- 地基包的规则模板在这里维护：改模板改这个仓库
- 改完后 push，以后新项目 clone 就能拿到最新版
- 已建的项目不会自动更新（各自独立演进），如需同步新规则手动合并
