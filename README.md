# project-base · 项目地基包

> 建新项目时，clone 这个仓库作为地基，省去从0建规则的过程。
> 地基里放的是"AI 怎么跟你协作"的元规则，不是某个项目的业务逻辑。

## 30秒看懂

**这是什么**：一套给 AI 编程工具（opencode/Cursor/Claude Code 等）用的"协作规则模板"。clone 下来作为新项目的地基，AI 每次开工自动读这些规则，不用你每次重复教。

**解决什么问题**：每次开新项目，AI 不知道你的协作习惯——不确认就动手、改了代码忘改文档、跨阶段提问。这套规则把踩过的坑沉淀成模板，新项目 clone 即用，不用从零踩一遍。

**适不适合你**：
- ✅ 用 opencode / Cursor 等 AI 编程工具，且开多个项目 → 适合
- ✅ 想让 AI 按你的习惯协作（先确认再动手、主动暴露盲区）→ 适合
- ❌ 只用一个项目、不换工具 → 不用，直接在那个项目里写规则就行
- ❌ 不用 AI 编程工具 → 只能用 markdown 规则文件，agent 和脚本用不了

**包含什么**：开发规则 + 产品/设计模板 + 10个协作Agent（双总监制衡）+ 6个规则文件 + 自动化脚本模板（Windows/Mac）+ 操作手册（AI读了引导你初始化）

**怎么开始**：往下看"怎么用"，3步跑通。

---

## 这是什么

建第一个项目的时候，打地基（AGENTS.md、AI自检清单、规则文件）花了很长时间，一边踩坑一边补规则。建第二个项目时发现——如果不把地基模板化，每个新项目都要从0踩一遍。

这个仓库就是把第一个项目打地基的过程沉淀成模板。建新项目时 clone 下来改改项目信息就能用。

## 怎么用

**详细的操作流程见 [操作手册](./操作手册.md)。** 下面是简要步骤：

### 1. clone 地基包

```bash
git clone git@github.com:lingmingying1995/project-base.git <新项目名>
cd <新项目名>
```

### 2. 打开 opencode，说"读操作手册，开始初始化项目"

AI 会读 `操作手册.md`，引导你完成项目初始化：
- 确认项目基本信息（项目名、描述、技术栈）
- 填写项目文件（AGENTS.md、PRODUCT.md、DESIGN.md）
- 配置 Git 和 Agent
- 验证 + 开始干活

全程 AI 引导，你只需要回答问题和确认。

### 3. 也可以手动操作

如果不使用 opencode，按 [操作手册](./操作手册.md) 的步骤手动完成。

## 地基包含什么

├── DESIGN.md               # 设计规范（空骨架，如有UI才填）
├── agents/                 # 开发协作 Agent（10个）
│   ├── project-director.md     # 项目总监：管需求方向、流程调度、业务取舍

│   ├── architect.md            # 架构师：评估改动对结构的影响
│   ├── ui-designer.md          # UI设计师：改前端样式和交互
│   ├── doc-maintainer.md       # 文档维护员：代码改了文档跟着改
│   ├── code-tester.md          # 代码测试员：改完后检查关联模块遗漏
│   ├── rule-tester.md          # 规则测试员：检查索引/规则/手册的同步
│   ├── quality-director.md     # 质量总监：全流程验收，检查完整性
│   └── task-guardian.md        # 定时任务守护：执行归档/同步，失败自动诊断修复

│   ├── sync.bat / sync.sh      # Git 自动同步（Windows / Mac）

├── 规则/

### Agent 协作流程

10个 Agent 按以下顺序协作，双总监制衡，覆盖"需求→分发→编码→验收→定时任务守护"全流程：

```
用户说需求
  → 项目总监：理解需求，调需求拆解员
  → 需求拆解员：拆成改动清单
  → 技术总监：接手，调架构师评估，安排编码
  → 主Agent 编码
  → UI设计师：如涉及UI，改样式和交互
  → 技术总监：调代码测试员、规则测试员
  → 项目总监：调文档维护员
  → 项目总监：调质量总监验收
  → 定时任务守护：执行归档/同步，失败自动诊断修复
```

**双总监制衡**：项目总监管需求方向和流程调度（做对的事），技术总监管技术方案和实现质量（把事做对）。两人都有一票否决权，僵持时升级给用户。

| Agent | 何时介入 | 做什么 | 改不改 |
|-------|---------|--------|--------|
| 项目总监 | 用户提需求时 | 管需求方向、流程调度、业务取舍 | 不改 |
| 技术总监 | 项目总监交接后 | 管技术方案、架构风险、代码质量 | 不改 |
| 需求拆解员 | 被项目总监调用 | 把用户需求拆成改动清单 | 不改 |
| 架构师 | 被技术总监调用 | 评估改动对结构的影响 | 不改 |
| 文档维护员 | 被项目总监调用 | 代码改了文档跟着改 | 直接改 |
| 代码测试员 | 被技术总监调用 | 检查"改了A没改B"的代码遗漏 | 只报告 |
| 规则测试员 | 被技术总监调用 | 检查索引/规则/操作手册的同步 | 只报告 |
| 质量总监 | 全流程后 | 检查流程完整性和数据一致性 | 能改的改 |
| 定时任务守护 | 定时任务执行时 | 执行归档/同步，失败自动诊断修复 | 能改的改（仅配置文件） |

**使用方式**：把 `agents/` 目录下的文件复制到项目的 `.skills-mirror/agents/` 或 `~/.config/opencode/agents/` 目录，opencode 会自动加载。如配了软链，直接生效。

## 地基包不包含什么

- 具体项目的产品功能定义（每个项目不同，写在 PRODUCT.md 里）
- 技术选型（每个项目不同，写在 AGENTS.md 里）
- 业务规则（如写稿规则、行业规范等）
- 代码（地基只管规则，不管代码）

## 核心理念

**规则管方向和底线，不管创意和判断。**

地基里的规则管的是"AI 怎么跟用户协作"（确认规则、不替用户决定），不管"AI 怎么思考"（创意、判断、角度）。AI 在创意和判断上要主动发挥，不要被规则框死。

## 维护

- 地基包的规则模板在这里维护：改模板改这个仓库
- 改完后 push，以后新项目 clone 就能拿到最新版
- 已建的项目不会自动更新（各自独立演进），如需同步新规则手动合并
