# project-base · 项目地基包（免费版）

> 建新项目时，clone 这个仓库作为地基，省去从0建规则的过程。
> 地基里放的是"AI 怎么跟你协作"的元规则，不是某个项目的业务逻辑。

## 30秒看懂

**这是什么**：一套给 AI 编程工具（opencode/Cursor/Claude Code 等）用的"协作规则模板"。clone 下来作为新项目的地基，AI 每次开工自动读这些规则，不用你每次重复教。

**解决什么问题**：每次开新项目，AI 不知道你的协作习惯——不确认就动手、改了代码忘改文档、跨阶段提问。这套规则把踩过的坑沉淀成模板，新项目 clone 即用，不用从零踩一遍。

**适不适合你**：
- ✅ 用 opencode / Cursor 等 AI 编程工具，且开多个项目 → 适合
- ✅ 想让 AI 按你的习惯协作（先确认再动手、主动暴露盲区）→ 适合
- ❌ 只用一个项目、不换工具 → 不用，直接在那个项目里写规则就行
- ❌ 不用 AI 编程工具 → 只能用 markdown 规则文件，agent 和脚本用不了

**包含什么**：开发规则 + 产品/设计模板 + 2个规则文件 + Git 同步脚本模板（Windows/Mac）+ 操作手册（AI读了引导你初始化）

**怎么开始**：往下看"怎么用"，3步跑通。

## 这是什么

建第一个项目的时候，打地基（AGENTS.md、AI自检清单、规则文件）花了很长时间，一边踩坑一边补规则。建第二个项目时发现——如果不把地基模板化，每个新项目都要从0踩一遍。

这个仓库就是把第一个项目打地基的过程沉淀成模板。建新项目时 clone 下来改改项目信息就能用。

## 怎么用

**详细的操作流程见 [操作手册](./操作手册.md)。** 下面是简要步骤：

### 1. clone 地基包

```bash
git clone git@github.com:lingmingying1995/project-base.git <新项目名>
cd <新项目名>
```

### 2. 打开 opencode，说"读操作手册，开始初始化项目"

AI 会读 `操作手册.md`，引导你完成项目初始化：
- 确认项目基本信息（项目名、描述、技术栈）
- 填写项目文件（AGENTS.md、PRODUCT.md、DESIGN.md）
- 配置 Git 和定时同步
- 验证 + 开始干活

全程 AI 引导，你只需要回答问题和确认。

### 3. 也可以手动操作

如果不使用 opencode，按 [操作手册](./操作手册.md) 的步骤手动完成。

## 地基包含什么

```
project-base/
├── README.md               # 本文件
├── 操作手册.md              # 初始化操作流程（AI读这个引导用户完成初始化）
├── 提示词手册.md            # 对AI说什么能干什么（用户日常翻阅）
├── AGENTS.md               # 开发规则（AI 必读）
│                            #   含"确认规则"2条核心协作规则
├── AI自检清单.md            # AI 反复犯的问题清单（空骨架，边做边加）
├── PRODUCT.md              # 产品说明（空骨架，填写项目信息）
├── DESIGN.md               # 设计规范（空骨架，如有UI才填）
├── agents/                 # 协作 Agent（付费版，免费版为空）
├── scripts/                # Git 同步脚本模板
│   ├── sync.bat / sync.sh      # Git 自动同步（Windows / Mac）
│   ├── write-task-log.ps1      # 任务日志写入器（sync.bat 调用）
│   └── README.md               # 使用说明
├── 规则/
│   ├── 文件组织规则.md      # 一个内容单元一个独立文件 + 原话必留 + 对话记录 + 索引维护
│   └── Git同步规则.md       # 攒着改 + 触发时提交 + 标准流程
└── 产出/                    # AI和系统自动生成（不手动编辑）
    ├── 每日总结/            # AI分析对话生成
    ├── 决策记录/            # 决策过程沉淀（AI主动记）
    ├── 任务日志/            # 定时任务执行日志
    └── 测试报告/            # 全量测试报告
```

## 地基包不包含什么

- 具体项目的产品功能定义（每个项目不同，写在 PRODUCT.md 里）
- 技术选型（每个项目不同，写在 AGENTS.md 里）
- 业务规则（如写稿规则、行业规范等）
- 代码（地基只管规则，不管代码）

## 核心理念

**规则管方向和底线，不管创意和判断。**

地基里的规则管的是"AI 怎么跟用户协作"（确认规则、不替用户决定），不管"AI 怎么思考"（创意、判断、角度）。AI 在创意和判断上要主动发挥，不要被规则框死。
